# Jira 티켓 자동 처리 규칙

이 프로젝트에서 Jira 백로그를 자동으로 처리할 때 지키는 규칙. 사이트는
`p28app.atlassian.net`, 프로젝트 키는 `KAN`. 상태 이름은 한국어다:
`해야 할 일` → `진행 중` → `검토 중` → `완료`. "In Review"에 해당하는 것은 **검토 중**.

## 남아 있으면 계속한다

**티켓 하나를 끝냈다고 멈추지 않는다.** 브랜치·PR·티켓 이동까지 끝나면 목록을 다시 읽고
다음 티켓으로 이어간다. 처리 가능한 티켓이 없을 때만 조용히 멈춘다. 주기 실행(30분 등)은
"놓친 것이 없는지 다시 보는 장치"이지 "30분에 하나씩"이라는 뜻이 아니다.

목록은 매번 새로 읽는다. 사람이 그 사이에 직접 처리했거나 상태를 옮겼을 수 있고,
`진행 중`·`검토 중`·`완료`인 티켓은 건드리지 않는다.

## 손대는 것과 손대지 않는 것

건드린다: 이 저장소의 앱 코드로 끝나는 것. 재현 방법이나 스크린샷이 있어 무엇이 잘못됐는지
확정할 수 있는 것.

건드리지 않는다: 제품·디자인 결정이 필요한 것, 코드 밖의 일(계정 확보, 인프라 이전, 외부
서비스 설정). 이런 티켓은 `해야 할 일`에 그대로 두고 **왜 자동으로 못 하는지만** 한국어
코멘트로 남긴다. "못 한다"가 아니라 "무엇을 정해주면 할 수 있는지"를 적는다.

**첨부파일을 먼저 연다.** 요약 한 줄로 판단하지 않는다 — 스크린샷 하나가 "재현 불가"를
"원인 확정"으로 바꾸는 경우가 실제로 있었다(KAN-27). 첨부는 Jira REST API로 받을 수 있다.

## 작업 방식

1. 티켓 키로 브랜치를 만든다(`KAN-27`). **main에 직접 커밋·푸시하지 않는다** — main은
   Vercel 프로덕션에 바로 배포된다.
2. 고친 뒤 전부 통과시킨다: `npx jest --maxWorkers=2`, `npx tsc --noEmit`, 변경 파일
   `eslint`, `npx expo export --platform web`.
3. `gh pr create`로 PR을 연다. Windows에서 `gh`가 PATH에 없으면
   `"/c/Program Files/GitHub CLI/gh.exe"` 전체 경로로 부른다.
4. 티켓을 `검토 중`으로 옮기고, **무엇을 왜 고쳤는지와 PR 링크**를 한국어 코멘트로 남긴다.
   증상이 아니라 원인을 적는다.
5. 작업이 끝나면 `main`으로 돌아온다.

## 마이그레이션

**적용까지 한다. 매번 승인을 묻지 않는다.**

```
supabase db push --linked -p "$SUPABASE_DB_PASSWORD" --yes
```

되돌릴 수 있기 때문이다 — 추가한 테이블·컬럼·함수는 지우거나 이전 정의로 되돌리면 그만이다.
`--dry-run`으로 무엇이 적용될지 먼저 확인하고, 적용한 뒤 티켓 코멘트에 어떤 마이그레이션을
넣었는지 적는다.

**되돌릴 수 없는 것은 데이터뿐이다.** `DROP COLUMN`이나 `DROP TABLE`처럼 행이 사라지는
변경은, 먼저 그 데이터를 백업해 두고(별도 테이블로 복사하거나 파일로 덤프) 나서 적용한다.
백업 없이 지우면 "롤백할 수 있다"는 말이 사실이 아니게 된다.

preview 배포도 프로덕션과 **같은 Supabase를 쓴다** — 마이그레이션에 격리는 없다. 그러니
조회 규칙(RLS·정책 함수)을 바꾸는 마이그레이션은 백필이 맞는지 적용 직후에 확인한다:
적용 전과 같은 행이 보이는지 실제로 조회해 볼 것.

## 도구

`jira.cjs`(스크래치패드)가 REST API를 감싼다: `todo KAN`, `issue <KEY>`,
`transitions <KEY>`, `move <KEY> "<상태>"`, `comment <KEY> "<본문>"`. 인증은 `.env`의
`JIRA_BASE_URL` / `JIRA_EMAIL` / `JIRA_API_TOKEN`. `JIRA_BASE_URL`은 사이트 루트여야 한다
(`https://p28app.atlassian.net`) — 보드 주소를 넣으면 JSON 대신 HTML이 돌아온다.

서브태스크는 Kanban 보드에 카드로 나오지 않는다. 사람이 "그런 티켓 없다"고 할 때 먼저
확인할 것.
